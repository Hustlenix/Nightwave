01 / PREMISE

A music player should be able to play music without asking another computer to do it.

NIGHTWAVE is a standalone hardware experiment: load your own audio files onto a microSD card, plug in headphones or use the built-in speaker, and control playback using physical inputs.

The T4 version deliberately removes the easiest shortcut. Instead of sending “play track 5” to a decoder module, the ESP32-S3 owns the filesystem, decoding, buffering, scheduling, DSP and audio transport.

02 / THE DIFFERENCE

NOT A MODULE
CARRIER.

COMMON SHORTCUT

MCU→DFPLAYER→AUDIO

The controller sends high-level commands while a dedicated module hides the filesystem, decoding and most audio complexity.

NIGHTWAVE / TARGET

SDMMC→DECODE→PCM→I²S

The firmware owns the whole playback path. That creates the real engineering work: latency, DMA, ring buffers, task synchronization, audio quality and failure recovery.

05 / ENGINEERING PROOF

DESIGN TARGET

Real-time audio that survives the ugly cases.

SD latency spikes, decoder stalls, pause/resume, seek, track changes and UI work all compete for time. The firmware must keep the audio path fed without clicks or underruns.

< 1audible glitch target during normal playback
12H+runtime design target before measured validation

VALIDATION REQUIRED

Battery life is measured, not advertised.

Final runtime will be reported only after a controlled full-discharge test with battery capacity, output mode, volume level and start/stop times documented.
