01 / PREMISE

A music player should be able to play music without asking another computer to do it.

NIGHTWAVE is a standalone hardware experiment: load music, synced .lrc lyrics and playlists onto microSD, then listen through the built-in speaker, wired headphones or the planned Bluetooth-audio path.

The T4 direction still removes the easiest shortcut. The device owns filesystem access, software MP3/WAV decode, PCM buffering, scheduling, DSP and output routing. ESP32-S3 remains the current baseline, but Bluetooth audio may force a dedicated subsystem or a platform change.

02 / THE DIFFERENCE

NOT A MODULE
CARRIER.

COMMON SHORTCUT

MCU→DFPLAYER→AUDIO

The controller sends high-level commands while a dedicated module hides the filesystem, decoding and most audio complexity.

NIGHTWAVE / TARGET

SDMMC→DECODE→PCM→ROUTE

The firmware owns the playback path, then routes decoded audio across speaker, wired and Bluetooth outputs. That adds output switching, mute policy, headphone detection, Bluetooth pairing/state and more failure modes on top of latency, DMA and buffering.

05 / ENGINEERING PROOF

DESIGN TARGET

Real-time audio that survives the ugly cases.

SD latency spikes, decoder stalls, pause/resume, seek, track changes and UI work all compete for time. The firmware must keep the audio path fed without clicks or underruns.

3×speaker · wired · Bluetooth output routes that must switch cleanly
TBDfinal battery capacity until Bluetooth + display architecture is locked

VALIDATION REQUIRED

Battery life is measured, not advertised.

Final runtime will be reported only after a controlled full-discharge test with battery capacity, output mode, volume level and start/stop times documented.

THE BOARD IS
THE PRODUCT.

COMPUTE / PROVISIONALESP32-S3*

Current baseline for filesystem, decode, buffers, DSP and UI; Bluetooth may change the platform decision.

STORAGE / COREmicroSD

MP3/WAV, .lrc lyrics, playlists and richer library metadata/cache.

DISPLAY / DECISIONLarger screen*

Lyrics, metadata, menus, battery state and engineering diagnostics; interface may move to SPI.

BLUETOOTH / NEWBT audio*

Major unresolved subsystem for wireless headphones and speakers.

HEADPHONE PATH / COREI²S DAC + AMP

Stereo 3.5 mm output with headphone detect for automatic routing.

SPEAKER PATH / COREDigital class-D

Independent built-in speaker output retained.

BATTERY / DECISIONLarger 1S pack*

The old ~2500 mAh assumption is obsolete; capacity and physical size are being reworked.

POWER / RECHECKCharge + path + gauge

USB-C, power path and fuel gauge remain; charger/regulator values must be re-qualified.

PCB + MECHANICAL4-layer direction*

More routing, RF keepout, test points and a larger armored enclosure around screen, battery and antenna constraints.
